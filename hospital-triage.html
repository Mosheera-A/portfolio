Hospital Triage – Technical Overview

This project is a web-based hospital triage system that supports emergency check-in for patients and an administrative dashboard for staff. It combines a relational MySQL database with a structured triage workflow so that patients are registered with priority level, symptoms, and demographic details, then placed into a queue with an estimated wait time.

The application separates concerns between data storage (MySQL schema for priority, patients, and rooms), business logic (priority rules and wait-time calculations), and presentation (HTML/CSS forms and tables). This makes it easier to extend the system with additional reports or integrations later.

Highlights

Architecture

  • Relational design: Normalized MySQL tables for priorities, patients, and rooms with foreign-key relationships.
  • Separation of concerns: Check-in form, queue display, and admin dashboard are organized into clear, focused views.
  • Extensibility: Designed so additional metrics (e.g., average wait time per priority) or new reports can be added with minimal changes.

Workflow & Features

  • Patient check-in: Emergency staff register patients with name, gender, symptoms, priority level, and arrival time.
  • Queue management: System tracks each patient’s status and approximate wait based on priority rules.
  • Admin dashboard: Admin view to monitor the queue, assign rooms, and update patient status as they are seen.

Data Model

  • priority: Stores triage levels (e.g., urgent, non-urgent, critical) and an approximate wait-time guideline for each level.
  • patients: Captures patient details such as name, gender, symptoms, priority id, arrival time, and current status.
  • rooms: Represents treatment rooms with current status (available/occupied) and links to assigned patients when applicable.
